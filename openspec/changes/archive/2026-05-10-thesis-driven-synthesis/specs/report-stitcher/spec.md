# report-stitcher Specification (delta)

## MODIFIED Requirements

### Requirement: Render report shape with intro, headings, sources

The output Markdown SHALL contain, in order: a `# <task>` H1 title, a single line "Generated by Sheldon on `<ISO date>`. Researched for `<duration>`.", the intro paragraph, a `## <heading>` H2 per section followed by its body, a `## Conclusion` H2 followed by the outro, and a `## Sources` H2 followed by the bibliography list.

Heading source depends on the synthesis path:

- **Thesis path (default)**: each section's H2 is `claim.headline` rendered verbatim. Headlines come from the `thesis-drafter` capability already in plain English Title Case (3–8 words, e.g., `Wage Arbitrage Erosion`). NO slug-rendering is applied — they are already display-ready.
- **Cluster fallback path**: each section's H2 is the kebab-case cluster label rendered through the S1 Title-Case + initialism transform (`ai-patents-fuel-profit` → `AI Patents Fuel Profit`). Initialism set unchanged from S1.

In both paths, storage / event payloads / `topic_tag` columns continue to carry the underlying string format (kebab-case for cluster labels, plain-English for headlines).

#### Scenario: Six sections rendered in order on the thesis path

- **GIVEN** a thesis path with 6 surviving claims whose headlines are `Wage Arbitrage Erosion`, `FTE Pricing Collapse`, `GCC Captive Competition`, `Cannibalization Risk`, `Named Player Responses`, `AI-Native Disruption`
- **WHEN** `stitchReport(...)` runs
- **THEN** the output contains exactly 6 H2 section headings in order, each rendered verbatim from `claim.headline` (no transformation)
- **AND** also exactly one `## Conclusion` and one `## Sources` H2 each

#### Scenario: Cluster fallback retains S1's slug rendering

- **GIVEN** the synthesis orchestrator emits `synthesis.fallback` and the cluster path runs with sections labeled `ai-patents-fuel-profit`
- **WHEN** `stitchReport(...)` runs
- **THEN** the output contains the line `## AI Patents Fuel Profit` (S1 rendering preserved)

## ADDED Requirements

### Requirement: Intro and outro receive thesis text and per-claim metadata

`writeIntro` and `writeOutro` SHALL accept thesis-path-aware inputs in addition to the existing legacy signature. The new shape:

```ts
writeIntro(task, sectionLabels, runStats, thesis?: {
  thesisSentences: string[],
  claimHeadlines: string[],
})

writeOutro(task, sectionLabels, runStats, thesis?: {
  thesisSentences: string[],
  claimHeadlines: string[],
  claimMetadata: Array<{ headline, contested: boolean }>,
})
```

When `thesis` is undefined (cluster fallback path), the functions MUST behave exactly as in S1 — receive only labels, produce framing prose. When `thesis` is present (thesis path), the prompts SHALL be rewritten to:

- **Intro**: state the thesis directly. Do NOT paraphrase the headline list. The intro should read as a real opening to a research argument.
- **Outro**: synthesize what the report concluded. Explicitly flag any `claimMetadata.contested === true` claims as open questions ("X remains contested in the literature").

#### Scenario: Thesis-aware intro states a claim

- **GIVEN** thesis sentences asserting a 3-part argument and 5 claim headlines
- **WHEN** `writeIntro(task, labels, stats, thesis)` is called
- **THEN** the returned text contains substantive language reflecting the thesis sentences
- **AND** does NOT consist purely of "This report explores X, Y, Z" structure

#### Scenario: Outro flags contested claims as open

- **GIVEN** `claimMetadata` where 1 of 5 claims has `contested === true`
- **WHEN** `writeOutro(task, labels, stats, thesis)` is called
- **THEN** the returned text contains language identifying that the contested claim is open / disputed / unresolved

#### Scenario: Cluster fallback skips thesis prompt path

- **GIVEN** the cluster fallback path is active (no `thesis` argument passed)
- **WHEN** `writeIntro(task, labels, stats)` is called
- **THEN** the returned text follows the S1 prompt (framing-only, no fabricated thesis claims)
