# report-stitcher Specification

## Purpose

Pure function that takes intro + ordered sections (each with local 1..N citations) + outro + a fact lookup table, and produces a single Markdown report. Renumbers all section-local `[N]` references to globally unique `[M]` numbers in first-appearance order, collapsing duplicate URLs to a single global number. Renders an H1 task title, byline, intro, H2-headed sections, Conclusion, and a Sources bibliography. No I/O — orchestrators handle the file write.

## Requirements
### Requirement: Renumber section-local citations to globally unique numbers

The `stitchReport(input)` function SHALL accept `{task, intro, sections, outro, factsById, runStats}` where each `section` is `{label, body, factIds[]}` (the per-section fact set in the order they were given to the section-writer; section-local `[N]` citations correspond to 1-based positions in this list). The stitcher MUST produce a single Markdown string in which:

- Each section's local `[N]` citations are rewritten to globally unique `[M]` numbers, with citations preserved in first-appearance order across the whole report.
- The same source URL referenced by two distinct sections gets a single global number that's reused.
- A trailing `## Sources` block lists each global `[M]` once with `<title>` (or URL fallback) and `<url>`.

#### Scenario: Same URL across sections gets single global number

- **GIVEN** section A's localId 3 and section B's localId 1 both reference the same `source_url`
- **WHEN** the stitcher renumbers
- **THEN** section A's `[3]` and section B's `[1]` both render as the same `[M]`
- **AND** the Sources block contains exactly one `[M] ... <url>` line for that URL

### Requirement: Render report shape with intro, headings, sources

The output Markdown SHALL contain, in order: a `# <task>` H1 title, a single line "Generated by Sheldon on `<ISO date>`. Researched for `<duration>`.", the intro paragraph, a `## <heading>` H2 per section followed by its body, a `## Conclusion` H2 followed by the outro, and a `## Sources` H2 followed by the bibliography list.

Heading source depends on the synthesis path the orchestrator selected, signalled via `input.path`:

- **Thesis path (`path: 'thesis'`)**: each section's H2 is `claim.headline` rendered verbatim. Headlines come from the `thesis-drafter` capability already in plain English Title Case (3–8 words, e.g., `Wage Arbitrage Erosion`). NO slug-rendering is applied — they are already display-ready.
- **Cluster fallback path (`path: 'cluster'`, default)**: each section's H2 is the kebab-case cluster label rendered through the Title-Case + initialism transform (`ai-patents-fuel-profit` → `AI Patents Fuel Profit`). Initialism set: `ai`, `genai`, `llm`, `gpt`, `ml`, `mlops`, `bpo`, `rag`, `roi`, `sla`, `api`, `csr`, `bot`, `bott`, `it`, `kpi`, `crm`, `gdpr`, `ccpa`, `hipaa`.

In both paths, storage / event payloads / `topic_tag` columns continue to carry the underlying string format (kebab-case for cluster labels, plain-English for headlines).

#### Scenario: Six sections rendered in order on the thesis path

- **GIVEN** a thesis path with 6 surviving claims whose headlines are `Wage Arbitrage Erosion`, `FTE Pricing Collapse`, `GCC Captive Competition`, `Cannibalization Risk`, `Named Player Responses`, `AI-Native Disruption`
- **WHEN** `stitchReport(...)` runs with `path: 'thesis'`
- **THEN** the output contains exactly 6 H2 section headings in order, each rendered verbatim from `claim.headline` (no transformation)
- **AND** also exactly one `## Conclusion` and one `## Sources` H2 each

#### Scenario: Cluster fallback retains slug rendering

- **GIVEN** the synthesis orchestrator emits `synthesis.fallback` and the cluster path runs with sections labeled `ai-patents-fuel-profit`
- **WHEN** `stitchReport(...)` runs with `path: 'cluster'`
- **THEN** the output contains the line `## AI Patents Fuel Profit`

#### Scenario: Initialism preservation on cluster path

- **GIVEN** a section with `label = 'ai-patents-fuel-profit'` and `path: 'cluster'`
- **WHEN** the stitcher renders the H2
- **THEN** the output contains the exact line `## AI Patents Fuel Profit`
- **AND** does NOT contain `## Ai Patents Fuel Profit`

#### Scenario: Storage and event payloads unchanged

- **WHEN** the cluster step emits a `cluster.computed` event with `payload.sizes[].label = 'ai-patents-fuel-profit'`
- **THEN** the event payload contains that kebab-case label, NOT a Title-Cased version
- **AND** the per-section `section.written` event payload's `label` field carries the same string format used for that section's heading (kebab-case for cluster path, plain-English headline for thesis path)

### Requirement: Intro and outro receive thesis text and per-claim metadata

`writeIntro` and `writeOutro` SHALL accept thesis-path-aware inputs in addition to the existing legacy signature. The new shape:

```ts
writeIntro(task, sectionLabels, runStats, thesis?: {
  thesisSentences: string[],
  claimHeadlines: string[],
})

writeOutro(task, sectionLabels, runStats, thesis?: {
  thesisSentences: string[],
  claimHeadlines: string[],
  claimMetadata: Array<{ headline, contested: boolean }>,
})
```

When `thesis` is undefined (cluster fallback path), the functions MUST behave exactly as before — receive only labels, produce framing prose. When `thesis` is present (thesis path), the prompts SHALL be rewritten to:

- **Intro**: state the thesis directly. Do NOT paraphrase the headline list. The intro should read as a real opening to a research argument.
- **Outro**: synthesize what the report concluded. Explicitly flag any `claimMetadata.contested === true` claims as open questions ("X remains contested in the literature"). The prompt MUST forbid the model from inventing contention when no headline is marked contested.

#### Scenario: Thesis-aware intro states a claim

- **GIVEN** thesis sentences asserting a 3-part argument and 5 claim headlines
- **WHEN** `writeIntro(task, labels, stats, thesis)` is called
- **THEN** the returned text contains substantive language reflecting the thesis sentences
- **AND** does NOT consist purely of "This report explores X, Y, Z" structure

#### Scenario: Outro flags contested claims as open

- **GIVEN** `claimMetadata` where 1 of 5 claims has `contested === true`
- **WHEN** `writeOutro(task, labels, stats, thesis)` is called
- **THEN** the returned text contains language identifying that the contested claim is open / disputed / unresolved

#### Scenario: Outro does not invent contention when nothing is contested

- **GIVEN** `claimMetadata` where every entry has `contested === false`
- **WHEN** `writeOutro(task, labels, stats, thesis)` is called
- **THEN** the returned text does NOT contain the words "contested", "disputed", "divided", or "remains open"

#### Scenario: Cluster fallback skips thesis prompt path

- **GIVEN** the cluster fallback path is active (no `thesis` argument passed)
- **WHEN** `writeIntro(task, labels, stats)` is called
- **THEN** the returned text follows the legacy framing-only prompt

### Requirement: Pure function

`stitchReport` MUST be pure: it takes its input and returns its output, with no I/O or events. Filesystem writing is the orchestrator's job, not the stitcher's.

#### Scenario: Multiple calls with identical input return identical output

- **GIVEN** a fixed `input` object
- **WHEN** `stitchReport(input)` is called twice
- **THEN** both invocations return byte-identical strings
